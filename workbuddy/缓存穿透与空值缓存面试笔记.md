# 缓存穿透（空值缓存）面试笔记

> 苍穹外卖项目缓存三大问题的最后一块拼图——穿透，本文档说明原理、落地实现与面试要点。

---

## 一、什么是缓存穿透

缓存穿透是指：**查询一个「根本不存在」的数据**（数据库里也没有），由于缓存里也查不到，请求直接穿透缓存打到数据库。

典型场景：恶意攻击者用脚本构造大量不存在的 key（如不存在的分类 id），大量请求绕过缓存直接压数据库，导致数据库被打挂。

```
请求(不存在的categoryId=99999) → 查缓存(未命中) → 查数据库(也没有) → 返回空 → 缓存不写入
                                                          ↑
                            每次请求都走到这里 → 数据库被空查询打穿
```

## 二、三大缓存问题区分（易混点）

| 问题 | 触发条件 | 本质 | 防护手段 |
|------|----------|------|----------|
| **穿透** | 查不存在的 key | 缓存和 DB 都没有 | 空值缓存 / 布隆过滤器 / 参数校验 |
| **击穿** | 某热点 key 过期瞬间 | 缓存失效、DB 有数据 | 互斥锁 / 逻辑过期 |
| **雪崩** | 大量 key 同时过期 | 缓存集体失效 | 随机 TTL / 多级缓存 / 熔断降级 |

## 三、本项目落地实现（空值缓存）

### 场景

用户端 `DishController#list(categoryId)`，根据分类 id 查菜品。原代码：

```java
if (list != null && list.size() > 0) {
    return Result.success(list);   // 只命中非空列表
}
// 空结果不缓存，每次都查库
```

**问题**：分类 id 不存在（或分类下无菜品）时，`listWithFlavor` 返回空列表，上述判断把空列表当「未命中」，每次都查库。

### 方案：空值缓存

查库后若结果为空，也缓存一个「空值标记」，短过期时间，下次命中直接返回空：

```java
if (list == null || list.isEmpty()) {
    // 缓存空值标记，短过期时间 5 分钟
    redisTemplate.opsForValue().set(key, EMPTY_LIST, EMPTY_TTL_MINUTES, TimeUnit.MINUTES);
    return Result.success(Collections.emptyList());
}
```

### 关键设计点

1. **空值过期时间要短**（5 分钟 << 正常缓存 30~40 分钟）：
   - 分类后续新增菜品后，空标记很快过期，不会让用户长时间读不到新数据。
2. **一致性闭环**：管理端增删改菜品时 `clearCache("dish_*")` 会清理 `dish_{id}` 空值标记（key 前缀一致），
   所以空标记不会成为「脏数据」长期存在。
3. **与击穿防护协同**：空值缓存写在「获取互斥锁 → 查库」之后，仍然先走 setIfAbsent 互斥锁，
   避免并发穿透时空查询打库。

## 四、三种穿透防护方案对比

| 方案 | 原理 | 优点 | 缺点 | 适用 |
|------|------|------|------|------|
| **空值缓存**（本项目） | 查不到也缓存一个空标记 | 实现简单、成本低 | 内存占用（可控）、短暂不一致 | 空值场景少、可控 |
| **布隆过滤器** | 用位图快速判断 key 是否存在 | 内存极小、无 DB 压力 | 有误判率、数据删除复杂、需预加载 | 海量 key、黑名单 |
| **参数校验** | 入口拦截非法参数 | 最彻底、零成本 | 无法覆盖所有业务规则 | 非法 id、非法格式 |

> 面试话术：本项目用「空值缓存 + 短过期时间」，配合已有的「互斥锁防击穿」「随机 TTL 防雪崩」，
> 形成完整的三级缓存防护体系。如果数据量更大、空值 key 不可枚举，再引入布隆过滤器。

## 五、布隆过滤器（扩展，加分项）

原理：用 N 个哈希函数把 key 映射到位数组的多个位置，判断 key 是否存在：

- **不存在一定不存在**（无误漏），**存在可能是误判**（有误判率）
- 内存占用极小（1 亿 key 约几百 MB）
- 缺点：不能删除（计数布隆可解决）、需预加载已有 key

适用场景：海量 key 且大部分不存在时，先用布隆过滤器挡掉大部分无效请求，剩下的再查缓存/DB。

## 六、速记表

| 维度 | 要点 |
|------|------|
| 穿透本质 | 查「不存在」的数据，缓存和 DB 都没有 |
| 空值缓存核心 | 查不到也缓存空标记 + 短过期时间 |
| 空值 TTL | 短（5 分钟），避免分类新增菜品后读不到 |
| 一致性 | 管理端 clearCache("dish_*") 连带清空标记 |
| 三方案 | 空值缓存 / 布隆过滤器 / 参数校验 |
| 布隆缺点 | 有误判率、不能删除、需预加载 |

## 七、改动文件

- `user/DishController.java`：`list` 方法加入空值缓存（`EMPTY_LIST` 标记 + `EMPTY_TTL_MINUTES=5`）
- 套餐（`@Cacheable` 缓存的是 `Result` 包装对象，永远非 null），空列表天然被缓存，穿透风险低，未额外改动

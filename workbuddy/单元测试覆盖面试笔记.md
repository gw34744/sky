## 二、三类测试的设计思路

### 1. Controller 层测试（OrderControllerTest）

测下单接口的**幂等逻辑**，覆盖 4 个分支：

```
token 缺失 → 拒绝
token 与缓存不一致（被篡改）→ 拒绝
token 一致 → 删除 token + 正常下单
token 已被使用（缓存为空，重复提交）→ 拒绝
```

**关键技术点**：`BaseContext` 是 ThreadLocal 静态上下文，测试里不用 `mockStatic`（那需要 mockito-inline 依赖），而是直接 `BaseContext.setCurrentId(1001L)` 设置、`@AfterEach` 里 `removeCurrentId()` 清理。这样零额外依赖、更贴近真实。

### 2. 缓存击穿并发测试（DishControllerTest）

这是**最有技术含量**的一个。用 `CountDownLatch` + 线程池 + `AtomicReference` 模拟 10 个线程同时请求同一分类，验证：

```java
// 核心断言：并发击穿时查库只发生一次
assertEquals(1, dbQueryCount.get(), "并发击穿时查库应只发生一次");
```

**设计要点**：
- `AtomicReference<List<DishVO>>` 充当「内存缓存」，查库后写入，后续线程能读到；
- `setIfAbsent` 用 `AtomicInteger.compareAndSet(0, 1)` 模拟互斥锁的原子性；
- `CountDownLatch` 让所有线程同时起跑，制造真正的并发竞争。

**这测试证明了什么**：缓存击穿防护（互斥锁 setIfAbsent + 自旋）真的有效——即使 10 个线程同时打过来，查数据库也只发生 1 次。

### 3. 参数校验边界测试（GlobalExceptionHandlerTest）

测 `MethodArgumentNotValidException` 的处理：
- 有字段错误 → 返回第一个字段的错误信息（如"收货地址不能为空"）；
- 无字段错误 → 返回兜底"参数校验失败"。

**为什么测这个**：参数校验（JSR-303）是之前补的 `@Valid` + `@NotBlank/@NotNull` 能力，异常处理是它的后半段——校验失败后怎么优雅返回给前端。测它保证这条链路完整。

## 三、测试的几个技术点（面试可讲）

### 1. 为什么用 Mockito 而不是 @SpringBootTest？

| 方式 | 优点 | 缺点 |
|------|------|------|
| Mockito 单元测试 | 快（毫秒级）、隔离、不依赖外部 | 不测 Spring 装配 |
| @SpringBootTest 集成测试 | 测完整链路 | 慢（秒级）、需连 DB/Redis |

本项目 Service/Controller 用 Mockito 快测，只有 RabbitMQ 用集成测试（因为要验证真实连接）。**分层策略**：纯逻辑用单测，跨中间件用集成测试。

### 2. mockStatic 为什么需要 mockito-inline？

`mockStatic` 只能 mock 静态方法，需要 Mockito 的 inline mock maker（基于 Instrumentation API）。默认的 SubclassByteBuddyMockMaker 不支持。**项目里绕过了这个坑**：BaseContext 是 ThreadLocal，直接 set 值即可，不需要 mock 静态方法。

### 3. 并发测试怎么保证「同时」？

用 `CountDownLatch`：所有线程先 `ready.countDown()` 就位，主线程 `start.countDown()` 一声令下同时放行，`done.await()` 等所有线程跑完再断言。这是并发测试的标准写法。

### 4. 测试能证明「击穿只查一次库」为什么重要？

这是把「缓存击穿防护」从「代码写了」变成「确实有效」的关键。面试官问"你怎么证明你的击穿防护生效"，能答"我写了个 10 线程并发的单测，断言查库只发生一次"——这是很强的证据。

## 四、高频面试问答

**Q1：你项目测试覆盖怎么样？**
A：63 个用例，覆盖 5 个核心 Service（分类/员工/订单/菜品/购物车）业务逻辑、Controller 层幂等、缓存击穿并发、参数校验异常、订单状态机、RabbitMQ 集成链路，以及**管理端登录端到端集成测试**（真实 HTTP + MySQL + Redis + JWT 认证全链路）。用 Mockito 做单元测试 + SpringBootTest 做端到端集成测试。

**Q2：单元测试和集成测试怎么区分？**
A：单元测试 mock 所有外部依赖（DB、Redis、MQ），只测本层逻辑，快且隔离；集成测试用 `@SpringBootTest` 连真实中间件，走完整 HTTP → 拦截器 → Service → DB 链路，验证各层协作。前者多、后者少。

**Q2.5：端到端集成测试怎么做？**
A：用 `@SpringBootTest(webEnvironment = RANDOM_PORT)` + `TestRestTemplate` 发真实 HTTP 请求，不 mock 任何层。覆盖登录（BCrypt 校验 + JWT 生成）、带 token 访问受保护接口、无 token/伪造 token 返回 401、真实 Redis 缓存查询。用 `@Order` 控制顺序，登录拿到的 token 复用给后续受保护接口。

**Q3：为什么缓存击穿要专门写并发测试？**
A：因为击穿是「并发场景」才暴露的问题，串行测试测不出来。必须用多线程模拟并发，才能验证互斥锁真的让查库只发生一次。

**Q4：测试里 ThreadLocal 怎么处理？**
A：测试前 `set`，测试后 `@AfterEach` 里 `remove`，避免 ThreadLocal 残留污染其他测试（尤其在多线程环境）。

## 三、已修复的问题（本次）

### 1. 下单接口缺事务（严重）✅ 已修复

**问题**：`OrderServiceImpl.submitOrder` 有 3 次数据库写操作（插订单、批量插明细、清购物车），
但方法上没有 `@Transactional`。若第 2/3 步失败，会产生"有订单无明细"或"订单生成但购物车未清"的脏数据。

**修复**：给 `submitOrder` 方法添加 `@Transactional` 注解。

```java
@Transactional
public OrderSubmitVO submitOrder(OrdersSubmitDTO ordersSubmitDTO) { ... }
```

**面试价值**：能讲出"事务的 ACID 特性 + 为什么下单必须保证原子性 + 事务失效的常见原因
（自调用、异常被吞、非 public 方法等）"。

### 2. 订单号用时间戳（并发撞号）✅ 已修复

**问题**：`order.setNumber(String.valueOf(System.currentTimeMillis()))` —— 毫秒时间戳当订单号，
高并发下同一毫秒多个请求会生成相同订单号。

**修复**：新增 `SnowflakeIdUtil`（标准雪花算法），订单号改为 `SnowflakeIdUtil.nextIdStr()`。

雪花算法 64 位结构：
- 1 位符号位 + 41 位时间戳 + 10 位机器标识 + 12 位序列号
- 特性：趋势递增（利于索引）、分布式唯一、无第三方依赖
- 额外处理了「时钟回拨」异常场景
